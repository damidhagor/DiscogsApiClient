# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Each entry lists its own **Breaking** changes inline where applicable — see
[docs/MIGRATION_GUIDE.md](MIGRATION_GUIDE.md) for detailed before/after migration steps.

## [5.2.0] - Unreleased

- Fixed: `docs/API_COVERAGE.md` incorrectly listed `/oauth/access_token` as an unimplemented gap; it is
  already handled internally by the OAuth authentication flow and is not a public client endpoint.

## [5.1.0] - 2026-08-23

- Added new `IDiscogsApiClient` endpoints:
  - User Profile:
    - Edit profile (`UpdateUser()`).
  - User Collection:
    - Get custom collection fields (`GetCollectionFields()`).
    - Get collection release by release ID (`GetCollectionItemsByRelease()`).
    - Edit release instance notes/rating/folder (`UpdateCollectionFolderRelease()`).
    - Edit release instance custom field value (`UpdateCollectionFolderReleaseField()`).
  - User Contributions & Submissions:
    - Get user's database contributions (`GetContributions()`).
    - Get user's submissions (`GetSubmissions()`).
  - User Lists:
    - Get user's lists (`GetUserLists()`).
    - Get a list's details and items (`GetList()`).
  - Database - Releases:
    - Get user's rating for a release (`GetReleaseRating()`).
    - Set user's rating for a release (`UpdateReleaseRating()`).
    - Delete user's rating for a release (`DeleteReleaseRating()`).
- Fixed: `User.HomePage` was mapped to the wrong JSON property name (`"homepage"` instead of `"home_page"`),
  so it never deserialized from Discogs API responses.
- Fixed several contract properties that Discogs sometimes omits or returns as `null`, but were declared as
  non-nullable, causing `System.Text.Json` to silently deserialize a default value (or throw for value types)
  instead of surfacing the missing data:
  - `ListItemStats.User` — absent when the request is unauthenticated.
  - `CollectionFolderRelease.ResourceUrl` — absent from collection list responses (only present when adding a release).
  - `Pagination.PaginationUrls.NextPageUrl`/`LastPageUrl` — absent for the last/only page of results.
  - `ArtistRelease.MainReleaseId`/`Year` — absent for some artist release credits.
  - `User.NumCollection`/`NumWantlist`/`Email`/`NumUnread` — absent when the requester is not the profile owner.
  - `Release.ExtraArtists` — absent when the release has no extra artists.
  - `SearchResult.CatalogNumber`/`Year`/`Country`/`Format`/`Genres`/`Styles`/`Labels`/`Barcodes`/`CommunityStatistics`/`FormatCount`/`Formats`/`MasterReleaseUrl`
    — absent (or `null`) depending on the result's `ResultType` (e.g. artist/label results omit most release-specific fields).
- **Breaking:**
  - Renamed `GetCollectionFolderReleases()` to `GetCollectionItemsByFolder()` to pair it with the new
    `GetCollectionItemsByRelease()` endpoint and match the Discogs API documentation's endpoint name
    ("Collection Items By Folder"). The signature is unchanged.
  - The nullability fixes above change several property types to their nullable equivalents
    (e.g. `int` → `int?`, `string` → `string?`, `IReadOnlyList<T>` → `IReadOnlyList<T>?`):
    `ListItemStats.User`, `CollectionFolderRelease.ResourceUrl`, `PaginationUrls.NextPageUrl`/`LastPageUrl`,
    `ArtistRelease.MainReleaseId`/`Year`, `User.NumCollection`/`NumWantlist`/`Email`/`NumUnread`,
    `Release.ExtraArtists`, and the 12 `SearchResult` properties listed above.

## [5.0.0] - 2026-08-22

- Dropped .NET 6 and .NET 7 support; the library now targets **.NET 8, 9 and 10**.
- Migrated the client implementation from [Refit](https://github.com/reactiveui/refit) generation quirks and the legacy
  hand-rolled source generator to a fully rewritten, incremental (`IIncrementalGenerator`) source generator producing
  idiomatic, AOT-compatible client code.
- Removed client-side rate limiting; added `IDiscogsRateLimitStateService` for read-only access to the Discogs
  `x-discogs-ratelimit*` response headers so consumers can implement their own throttling/backoff strategy.
- Modernized service registration to use the `IOptions<T>` pattern with `ValidateOnStart` validation.
- Redesigned authentication provider registration around explicit, mutually exclusive opt-in calls.
- Converted `Contract` DTO collection properties from `List<T>` to `IReadOnlyList<T>` (98 properties) to prevent
  unintended mutation of API response data.
- Converted `OAuthAuthenticationSession.AuthorizeUrl`/`VerifierCallbackUrl` from `string` to `Uri`.
- Added `[GeneratedCodeAttribute]` and `// <auto-generated/>` headers to all generator output.
- **Breaking:**
  - `AddDiscogsApiClient` moved from the `DiscogsApiClient` namespace to `Microsoft.Extensions.DependencyInjection`.
  - Invalid options now throw `OptionsValidationException` at application startup (`ValidateOnStart`) instead of
    `InvalidOperationException` at registration time.
  - `[ApiClient]` now targets the internal implementing class instead of the `IDiscogsApiClient` interface; the
    interface itself is now a plain, generator-agnostic contract.
  - All `CancellationToken` parameters on `IDiscogsApiClient` methods are now **required** — the previous
    `CancellationToken cancellationToken = default` default value was removed.
  - `IDiscogsAuthenticationService`/`DiscogsAuthenticationService` were removed. Authentication is now opted into
    explicitly via `.WithPatAuthentication(...)` or `.WithOAuthAuthentication(...)` on the `IServiceCollection`;
    calling both throws `InvalidOperationException`, calling neither yields a valid, permanently unauthenticated
    client.
  - `IPersonalAccessTokenAuthenticationProvider`/`PersonalAccessTokenAuthenticationProvider` were renamed to
    `IDiscogsPatAuthenticationProvider`/`DiscogsPatAuthenticationProvider`.
  - `IOAuthAuthenticationProvider`/`OAuthAuthenticationProvider` were renamed to
    `IDiscogsOAuthAuthenticationProvider`/`DiscogsOAuthAuthenticationProvider`, and its constructor now takes an
    `IHttpClientFactory` instead of an `HttpClient`.
  - `DiscogsApiClientOptions.ConsumerKey`/`ConsumerSecret`/`VerifierCallbackUrl` were moved to the new
    `DiscogsOAuthOptions` type (bound from the `"Discogs:OAuth"` configuration section); a new `DiscogsPatOptions`
    type (bound from `"Discogs:Pat"`) holds the personal access token.
  - `DiscogsApiClientOptions.RateLimitOptions` was removed along with the rate-limiting feature.
  - `Contract` DTO properties previously typed `List<T>` are now typed `IReadOnlyList<T>`.
  - `OAuthAuthenticationSession.AuthorizeUrl` and `VerifierCallbackUrl` are now `Uri` instead of `string`.

## [4.1.1] - 2026-06-02

## [4.1.0] - 2026-03-10

- Added `ThumbnailUrl` property to `ReleaseArtist` model.
- Fixed year/released property mappings in `Release` and `MasterReleaseVersion` models.
- **Breaking:**
  - Renamed `Release.YearFormatted` → `ReleasedFormatted`.
  - Renamed `MasterReleaseVersion.Year` → `Released`.

## [4.0.0] - 2023-12-13

- Removed the [Refit](https://github.com/reactiveui/refit) library, which produces a client implementation that is
  not AOT compatible and won't be for the foreseeable future.
  - Replaced by a custom source generator which creates a client implementation at compile time. The public API of
    `IDiscogsApiClient` was not changed by this replacement.
  - JSON serialization replaced with a source-generated `DiscogsJsonSerializerContext`.
  - The Refit `ExceptionFactory` implementation moved into an `ErrorHandlingDelegatingHandler` middleware.
  - Added a demo project for an AOT-publishable console application using the DiscogsApiClient.
- **Breaking:**
  - The OAuth authentication flow changed: the single `AuthenticateWithOAuth` call using `GetVerifierCallback` was
    removed and replaced with two calls, `StartOAuthAuthentication` and `CompleteOAuthAuthentication`, allowing the
    flow to be handled linearly instead of via a callback function.
  - The `HttpClient` used by `OAuthAuthenticationProvider` now also uses the `ErrorHandlingDelegatingHandler`
    middleware.

## [3.1.0] - 2023-07-03

- Reusing previously obtained OAuth access tokens/secrets was moved into its own `Authenticate` method.
- Optional query parameters are now nullable and optional in the API call.
- Some internal interfaces and implementations were made public.

## [3.0.1] - 2023-04-02

- Fixed `Release.LowestPrice`/`MasterRelease.LowestPrice` deserialization failing due to a `null` value being sent
  by Discogs.
- Fixed a typo in the `ReleaseIdentifier` class name.
- Added better exception handling to the OAuth flow; `AuthenticationFailedDiscogsException` now contains the
  underlying exception which caused the authentication to fail, if one was thrown.

## [3.0.0] - 2023-03-20

- The client is now implemented with the [Refit](https://github.com/reactiveui/refit) library.
- The library now also targets .NET 7 and the .NET 8 preview.
- The client now supports rate limiting, handled with middleware in the `HttpClient`.
- Dependency injection registration is simplified to a single method call.
- Added demo projects to showcase how to get started.
- Improved test coverage.
- New Discogs API query parameters are now supported.
- **Breaking:**
  - Authentication was outsourced into the new `IDiscogsAuthenticationService`, offering both authentication flows
    simultaneously without needing to be configured at startup; a new HttpClient middleware handles authentication
    headers.
  - The contract classes were restructured into sub-namespaces and a few properties were renamed for clarity.
  - API call parameters are now validated and can throw on invalid input.

## [2.1.1] - 2022-11-07

- Fixed the URL not being formatted correctly for the `GetCollectionFolderReleasesByFolderIdAsync` method.

## [2.1.0] - 2022-10-22

- Added the missing pagination parameter to the `GetCollectionFolderReleasesByFolderIdAsync` method.

## [2.0.0] - 2022-09-25

- Refactored the library for dependency injection support:
  - Added `IServiceCollection` extension methods to support easy dependency injection.
  - Added `IDiscogsApiClient` interface for mocking and dependency injection.
  - The DiscogsApiClient's `HttpClient` is now injectable via the constructor and, if configured via the
    `IServiceCollection`, injected via `IHttpClientFactory`.
  - **Breaking:** Needed parameters for the `IAuthenticationProvider`s were moved from their constructors into
    their `IAuthenticationRequest` implementations.
- Sealed all classes for performance.

## [1.0.0] - 2022-09-06

- Initial release.
- Support for personal access token and OAuth 1.0a authentication flows.
- Implementation of API functions for user information, collection & wantlist and database queries.
